# Changes

🇷🇺 [Русский](CHANGELOG.md) · 🇬🇧 English

## 0.10.0
- **Docker only.** Installation without Docker (the `deploy/*.sh` scripts, nginx, systemd, the release archive) is removed: less code and fewer variants, and it works the same on any Linux. `install.sh` is shorter: it installs Docker (if missing), puts `compose.yaml` and `.env` in `/opt/tapokhub`, starts the container (with `--domain` also Caddy with HTTPS) and installs the `tapokhub` command. Running it again updates. New variables `TAPOK_VERSION` (the image version) and `TAPOK_BIND` (accept connections only from this computer). The installer is available at the short address `https://tapoksys.github.io/TAPOKHUB-Lampa-addon/install.sh`. `INSTALL.md` and `DOCKER.md` are merged into `INSTALL.md`. The “how it runs” flag (`runtime`, `TAPOK_RUNTIME`) is gone: the server is always in Docker.
- **A short plugin address:** the server also serves the plugin at `/t` (for example, `https://tapok.example.com/t`); the installer and the hint page show it first.
- **Security audit.** Registration is **closed** by default until the owner decides otherwise (before, it was open when the database had no entry). A successful sign-in of a known user does not use up the attempt limit. A per-user request rate limit (`TAPOK_RATE_LIMIT`, 1200 per minute by default) and a separate one for heavy actions (recommendations, creating collections: 30 per minute). A cap on simultaneous connections (256, the rest get 503) and a timeout for a silent connection. Security headers on every answer (`nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`), HSTS in Caddy. The token from the address stays out of the log even with `DEBUG`, and the main token is not written to the log. The `wikidata`, `prop` and `ids` fields are validated. Plugin: the CUB account token goes to a server address typed by hand only after the person confirms (a plugin taken from the server itself asks nothing). CI: the token has read-only permissions.

## 0.9.0-pre.6 (pre-release)
- **The common plugin.** One file for all servers: `https://tapoksys.github.io/TAPOKHUB-Lampa-addon/tapokhub.js` (GitHub Pages, updated with every release tag; built with `plugin/build.py --universal`, `scripts/build-site.sh`). You enter your own server address in Settings → TapokHub (“Enter the server address by hand” or from the clipboard); the plugin checks it through `/healthz` and resets the sign-in on the previous server when the server changes; the hub images come from the person's own server. Plugins with a baked-in address work as before. A `/healthz` route was added to the nginx configuration (`deploy/nginx/nginx-tapokhub-proxy.conf`, it arrives with an installer update).
- **HTTPS in Docker Compose with one setting.** `compose.yaml` gained an optional Caddy service (the `https` profile, off by default): `TAPOK_DOMAIN` and `COMPOSE_PROFILES=https` in `.env` switch on a Let's Encrypt certificate, removing the profile and `docker compose rm -sf caddy` switch it off. The visitor's address goes in `X-Real-IP`, and the server trusts it only from the addresses in the new `TAPOK_TRUSTED_PROXIES` variable (in compose it is the Caddy address).

## 0.9.0-pre.5 (pre-release)
- **English language.** The plugin interface is chosen by the Lampa language (Russian, Ukrainian and Belarusian give a Russian interface, every other language gives English): all plugin texts go through `TH.t()`, the Russian text is the key, and the English one lives in `plugin/src/core/i18n-en.js`. Server replies to the plugin follow the `Accept-Language` header (the plugin puts the Lampa language there), the Telegram bot answers in the Telegram language of whoever writes to it, and the administrator commands, the log, the hint page and the installer scripts take the language from `TAPOK_LANG`, otherwise from the system language, otherwise Russian (`server/tapokhub/core/i18n.py`, the catalog `i18n_en.py`). The server's default TMDB description language follows `TAPOK_LANG` too. The completeness of the English catalog is checked by tests (`plugin/tests/i18n.js`, `server/tests/test_i18n.py`). English documentation: `README.en.md`, `docs/en/`, `server/README.en.md`, `CHANGELOG.en.md`.
- **Demo server.** Limits per user: `TAPOK_LIMIT_MOVIES`, `TAPOK_LIMIT_TV`, `TAPOK_LIMIT_FRANCHISES` (the owner is not affected), and the `tapokhub users limit` command sets own limits for one user. The plugin shows the server message when a limit is reached. The README links to the open demo server.

## 0.9.0-pre.4 (pre-release)
- **Registration on the server** is switched in the plugin: Settings → TapokHub → “Registration on the server” → “Open” or “Closed”. Only the server owner (the first user) sees and changes the value, for the others the line says who configures it; the server answers 403 to anyone else's attempt (`GET`/`POST /lib/registration`). The `tapokhub users registration open|closed` command works as before.
- The repository moved to `TAPOKSYS/TAPOKHUB-Lampa-addon`; the Docker image is now `ghcr.io/tapoksys/tapokhub-lampa-addon`. The links in the documentation, `install.sh` and `compose.yaml` are updated.
- **The guide** `docs/GUIDE.md`: deployment (the installer, Docker, Docker behind your own nginx), all features with pictures, the Telegram bot, server management, copies and rollback, a reference. The screenshots were taken on a real Lampa with the `scripts/docs-screenshots.py` script.
- **The second code audit**, fixes: cleanup of the TMDB response cache (limit 512 MB; it used to grow without bound), limits per user (5000 items, 300 collections), the server's TMDB key is remembered only from the owner's requests, the bot does not stop silently when a Telegram response is cut off, the `tapokhub telegram list|clear` commands.
- **The Telegram bot** (Settings → TapokHub → Telegram): the bot token from @BotFather is entered in the plugin and stored on the server, no separate process is needed. The chat number does not need to be entered: after the token it is enough to send the bot `/start`, and the personal chat pairs itself (the pairing window is 5 minutes after entering the token or pressing “Pair chat”, personal chats only; a group is paired by entering its number; the page watches the state and reports the pairing). The bot searches movies and TV shows by title, adds and removes them from the library, switches collection tracking on and off; the commands are `/library`, `/regen`, `/id`. It answers only in its own chat (except `/id`, to find out a chat number), the token is never given out and does not get into the log. The token is checked and a test message is sent on saving; the API is `GET/POST /lib/telegram`.
- **Hub autostart** (Settings → TapokHub → “Start the hub when Lampa starts”, off by default, this device only): after Lampa starts there is a 5-second countdown and the hub opens. Any key pressed, touch, click or mouse wheel cancels the launch (ordinary keys work as always, “Back” is additionally swallowed so that Lampa does not exit the app); if the person opened another section themselves, Lampa was launched by a movie link or the hub is already open, there is no countdown.
- Tokens do not need to be typed: “Paste … from the clipboard” buttons for the Telegram bot token (it is searched inside the pasted text, so you can copy the whole @BotFather message), the chat number and the TapokHub access token. If the clipboard is unavailable (TV, http), manual input opens right away. The Telegram page shows which account the bot is tied to: it is one for all devices of that CUB account.
- A “Server” line appeared in the TapokHub settings: the server version and how it runs (“Docker” or “without Docker”). The server sends `runtime` in `/health` (`TAPOK_RUNTIME`, the image sets `docker`).

## 0.9.0-pre.3 (pre-release)
- **Docker**: an image in one container without nginx (`Dockerfile`, `compose.yaml`, `docs/DOCKER.md`); `amd64` and `arm64` images are published to `ghcr.io/petefree1/tapokhub-lampa-addon`. The access token is created on the first start, the administrator email and registration are set with environment variables, the image check is `scripts/docker-test.sh` (it is in CI too).
- **Working without a domain over http**: `install.sh` without `--domain` installs the server at the computer's address (`--host http://192.168.1.5`, detected itself by default). The server can serve the plugin, the images and the hint page itself (`TAPOK_WEB_DIR`), putting into the plugin the address it was reached at, and answers `/healthz`.
- “Library”: items are split into groups: movies, TV shows, animated movies, animated series, anime and manga (the keywords anime/manga/based on manga, including live-action adaptations, and Japanese animation), documentaries. At the top are filter buttons (“All” and one per group, with counts); the chosen one is highlighted. The group is determined by the server (the `group` field in `/lib/items`); with an old server the plugin splits by kind, movie or TV show.
- The plugin starts on Lampa 3.0.5 and newer (the threshold used to be 3.3.0, and on 3.0.5 the plugin disabled itself: the hub did not appear). The “TapokHub” item in the side menu is the third one; the order is written into the Lampa menu settings once, after that it can be changed in the menu editor.
- Adult content is excluded from collections: the TMDB `adult` flag and erotica keywords (erotic movie, softcore, sexploitation, erotica) hide an item automatically (in “Customize” it is visible in “Other”, it can be restored by hand); it is removed from search and recommendations entirely.
- Removing a movie from a collection: a long press on a card → “Remove from collection” (it comes back through “Customize”).
- The logo and cover of a composite universe (Marvel, the “Wizarding World”) are no longer taken from the first part of one of its collections: before, the Marvel universe was captioned with the Iron Man logo. Now such a universe has the title text and a cover by the best rating.
- A new setting “Open the movie straight through a torrent” (Settings → TapokHub → Playback, off by default): Enter on a card in the hub skips the movie page. If a torrent is chosen it is launched; if not, the parser search opens.
- The collection screen: the initial focus is on the first movie card, not on the “Customize” button; the button has a real gear.
- `deploy/setup.sh` sees the connection to nginx through a symlink in `sites-enabled` (before, it added a second `include`, and nginx rejected the config).
- Local torrents and settings are separated by server and token; the responses and queues of a previous account do not affect the new one.
- Confirmed entries deleted on another device are no longer loaded back; clearing is confirmed after the server answers.
- The settings change queue is kept until confirmed and is retried after a network error, including an app restart.
- A manual token is checked before the account is switched; a late sign-in answer after signing out is ignored.
- A ready release is installed without Node.js. A restart failure and a wrong health-check version restore the previous release and unit, including the old way of running.
- The sign-in attempt limit does not trust client CF-Connecting-IP/X-Forwarded-For; X-Real-IP is accepted only from the local proxy.
- Merging users moves settings and torrents in one transaction; on conflicts the later entry is kept.
- Thread SQLite connections and the library background queue are closed; tests no longer need an increased open-files limit.
- Regression checks for the plugin, the server and deployment were added to `scripts/test.sh`.

## 0.9.0-pre.2 (pre-release)
- **Installation with one command** on Debian/Ubuntu: `curl … install.sh | sudo bash -s -- --domain … --email …`. It downloads the release
  from GitHub, verifies the checksum, installs nginx and python3, sets up HTTPS (Let's Encrypt), lays out the server and the plugin.
- The plugin from a release gets the user's server address (`deploy.sh --host`), the address is remembered for updates.
- On a new installation registration is closed, the administrator email is written at installation.
- `deploy/setup.sh` (formerly `install.sh`): a separate nginx site for the domain, nginx changes are rolled back on error.
- The `tapokhub rollback` and `tapokhub uninstall [--purge]` commands; the deployment scripts stay on the server in `/opt/tapokhub/deploy`.
- A description for users (a README with a screenshot), `docs/INSTALL.md`.
