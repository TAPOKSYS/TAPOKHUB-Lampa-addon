# TapokHub: кеширующий прокси TMDB

🇷🇺 Русский · 🇬🇧 [English](README.en.md)

Зачем: из России TMDB заблокирован. Сервис хранит ответы TMDB в SQLite, картинки на диске и
отдаёт последнюю копию, если TMDB недоступен. Ключ TMDB берёт у самой Lampa.

## Что где
- `server/tapokhub/`: пакет сервиса (только стандартная библиотека Python). Слои: `core/` (ядро: настройки, хранилище, сеть), `libraries/` (Wikidata, логотипы TMDB), `modules/` (прокси, пользователи, библиотека франшиз, HTTP-слой), `cli.py`. Работает в контейнере Docker (`Dockerfile`, `compose.yaml`, установка: [docs/INSTALL.md](../docs/INSTALL.md))
- `/data/tapokhub.sqlite3` в контейнере: ответы API, индекс картинок, коллекции для прогрева
- `/data/img/<размер>/<файл>`: кеш картинок (предел 5 ГБ, лишнее удаляется по давности запроса)
- `/data/token`: секретный токен владельца (по нему без токена в адресе сервис отвечает 404)

## Команды
    R=tapokhub                                 # команда установщика; без него: docker compose exec tapokhub python -m tapokhub
    $R stats                                   # состояние: ключ, кеш, счётчики
    $R collections list                        # коллекции, которые сервис прогревает
    $R collections add pred "Хищник" 399       # добавить коллекцию TMDB (--extra movie:384018 для спин-оффов)
    $R collections remove pred
    $R warm                                    # прогреть кеш сейчас (сервис делает это сам каждые 6 часов)
    $R refresh-key                             # взять ключ из опубликованной Lampa
    docker compose logs -f                     # журнал (в папке установки)

## Библиотека и коллекции-франшизы
Хранится в той же SQLite (общая для всех устройств). API живёт под тем же токеном: `/tmdb/<токен>/lib/…`
(JSON, POST с телом JSON, CORS открыт). Ответы не кешируются.

| Запрос | Что делает |
|---|---|
| `GET status?kind=movie&id=11` | в библиотеке ли позиция и к какой франшизе относится |
| `POST items/add` `{kind,id}` / `items/remove` | одиночная позиция («В библиотеку») |
| `GET items` | одиночные позиции с карточками |
| `POST franchises` `{kind,id}` | «Создать коллекцию»: сборка идёт в фоне, вернётся статус `pending` |
| `GET franchises` / `GET franchises/<id>[?hidden=1]` | список / состав по группам (`hidden=1` — режим настройки) |
| `POST franchises/<id>/hide` `{kind,id,hidden}` | скрыть или вернуть позицию |
| `POST franchises/<id>/add` `{kind,id}` / `item-remove` | добавить вручную / убрать добавленное вручную |
| `POST franchises/<id>/refresh` / `choose` `{wikidata,prop}` / `delete` | пересобрать / выбрать франшизу из предложенных / удалить |
| `GET search?query=` | поиск TMDB для ручного добавления |
| `GET events` / `POST events/seen` | что нового (для колокольчика Lampa) |

Статусы франшизы: `pending` → `resolving` → `ready`; также `needs_choice` (у позиции несколько франшизы в Wikidata:
в ответе `choices`), `error`, `merged` (совпала с уже существующей, в ответе `merged_into`).

**Откуда состав.** Коллекция TMDB + Wikidata (франшиза P8345 или серия P179 по идентификаторам TMDB): спин-оффы, сериалы,
мультсериалы. Группы: части доверенных коллекций TMDB (по названию коллекции), «Другие фильмы», «Скоро», «Сериалы»,
«Мультсериалы», «Прочее» (скрыто). Порядок внутри группы по дате выхода: у TMDB нет собственного порядка частей.
Пороги в начале `library.py`: фильм короче 60 минут или меньше 50 голосов, сериал меньше 100 голосов — в «Прочее».
Позицию, от которой создали коллекцию, и всё добавленное вручную автоматика не скрывает.

**Отслеживание.** Раз в сутки (после прогрева) франшизы пересобираются: новая позиция получает метку NEW на 14 дней и
событие `new_item`, новый сезон сериала — `new_season`. Скрытое и добавленное вручную при пересборке сохраняется.
Wikidata просит не частить: запросы идут с паузой 3 с и повтором при 429, ответы кешируются на 14 суток.

    $R library resolve movie 11      # собрать франшизу от позиции и показать состав
    $R library list | show <id> [--hidden] | refresh-all | logos

## Как ведёт себя кеш
- Ответы API: коллекция, фильм, логотипы 24 ч; поиск и подборки 10 мин; остальное 1 ч. Устаревшая копия
  отдаётся до 30 суток, если TMDB недоступен.
- Картинки не меняются: хранятся, пока не понадобится место.
- Ключ `api_key` в ключ кеша не входит: у клиентов ключи разные, данные одни.

## Обновление, откат, токен
Обновление, откат и копии: [docs/INSTALL.md](../docs/INSTALL.md). Сменить токен владельца: `docker compose exec tapokhub rm /data/token`, затем `docker compose restart tapokhub` (создастся новый; плагину на устройствах нужен новый токен).

## Известные ограничения
- Токен вшит в `tapokhub.js`, который отдаётся публично, поэтому это защита от случайного, а не от
  целенаправленного использования. Прокси пропускает только запросы к api.themoviedb.org и
  image.tmdb.org, произвольные адреса не проксируются.
- Через прокси идут только запросы, относящиеся к нашим коллекциям (см. `TH.proxy` в `src/core.js`).
  Остальной трафик Lampa использует её штатные зеркала.


## Пользователи и вход

У каждого пользователя своя библиотека (коллекции, отдельные фильмы и сериалы, события). У каждого устройства свой токен;
его хеш лежит в базе (`users`, `devices`), токен из `/data/token` работает как токен владельца (пользователь 1).
Публичный плагин токена не содержит: его получают при входе.

```
R=tapokhub
$R users list                       # пользователи и их устройства
$R users add почта@example.com      # заранее завести пользователя (нужно только при закрытой регистрации)
$R users registration open|closed   # регистрация новых пользователей при входе через CUB (по умолчанию открыта)
$R users merge <от> <к>             # слить пользователя в другого (устройства и данные)
$R users domain add имя [--http]    # доверенное зеркало CUB (--http: открывается только по http)
$R users email 1 почта@example.com  # владельцу (1) задать почту
$R users token <номер|почта>        # выдать токен для ручного ввода (Настройки -> TapokHub)
$R users revoke <номер устройства>  # отозвать токен устройства
$R users disable|enable <номер|почта>
```

Вход через CUB: `POST /tmdb/auth/cub` с `{domain, token, profile, device}`. Сервер спрашивает `https://<domain>/api/users/get`
(домен только из списка `TAPOK_CUB_DOMAINS`, по умолчанию cub.best, cub.black, durex.monster, cubnotrip.top, bylampa.online),
и выдаёт токен устройства; новая почта регистрируется как новый пользователь (пока регистрация не закрыта). Токен аккаунта не сохраняется. Не больше 12 попыток за
10 минут с одного адреса. `GET /tmdb/<токен>/whoami` покажет, чей это токен.
