# Изменения

🇷🇺 Русский · 🇬🇧 [English](CHANGELOG.en.md)

## 0.10.0
- **Только Docker.** Установка без Docker (скрипты `deploy/*.sh`, nginx, systemd, архив релиза) убрана: меньше кода и меньше разных вариантов, одинаково работает на любом Linux. `install.sh` стал короче: ставит Docker (если его нет), кладёт `compose.yaml` и `.env` в `/opt/tapokhub`, запускает контейнер (с `--domain` ещё и Caddy с HTTPS), ставит команду `tapokhub`. Повторный запуск обновляет. Новые переменные `TAPOK_VERSION` (версия образа) и `TAPOK_BIND` (принимать подключения только с этого компьютера). Установщик доступен по короткому адресу `https://tapoksys.github.io/TAPOKHUB-Lampa-addon/install.sh`. Документы `INSTALL.md` и `DOCKER.md` объединены в `INSTALL.md`. Признак «как запущен» (`runtime`, `TAPOK_RUNTIME`) убран: сервер всегда в Docker.
- **Короткий адрес плагина:** сервер отдаёт плагин и по `/t` (например, `https://tapok.example.com/t`), установщик и страница-подсказка показывают его первым.
- **Аудит безопасности.** Регистрация по умолчанию **закрыта**, пока владелец не решил иначе (раньше без записи в базе была открыта). Удачный вход известного пользователя не тратит лимит попыток. Ограничение частоты запросов на пользователя (`TAPOK_RATE_LIMIT`, по умолчанию 1200 в минуту) и отдельное для тяжёлых действий (рекомендации, создание коллекций: 30 в минуту). Потолок одновременных соединений (256, остальным 503) и таймаут молчащего соединения. Заголовки безопасности во всех ответах (`nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`), HSTS в Caddy. Токен из адреса не попадает в журнал даже при `DEBUG`, главный токен не пишется в журнал. Проверка полей `wikidata`, `prop` и `ids`. Плагин: токен аккаунта CUB уходит на введённый руками адрес сервера только после подтверждения человека (для плагина, взятого с самого сервера, вопроса нет). CI: права токена только на чтение.

## 0.9.0-pre.7 (pre-release)
- **Короткий адрес общего плагина:** `https://tapoksys.github.io/t.js`. Файл лежит в отдельном репозитории `TAPOKSYS/TAPOKSYS.github.io` и только подгружает настоящий плагин с GitHub Pages основного репозитория, поэтому обновляется вместе с релизами, а адрес не меняется. Прежний длинный адрес продолжает работать.
- **Меню настроек** разложено по группам с заголовками. Главная страница: «Подключение» (сервер, адрес, авторизация), «Главный экран» (анимация, автозапуск), «Просмотр и библиотека» (воспроизведение, удаление коллекции), «Уведомления» (Telegram), «Сервер: для владельца» (регистрация), «О плагине» (версия). Страницы авторизации, Telegram, воспроизведения, анимации и области помех поделены заголовками так же.

## 0.9.0-pre.6 (pre-release)
- **Общий плагин.** Один файл для всех серверов: `https://tapoksys.github.io/TAPOKHUB-Lampa-addon/tapokhub.js` (GitHub Pages, обновляется с каждым тегом релиза; сборка `plugin/build.py --universal`, `scripts/build-site.sh`). Адрес своего сервера вводится в Настройки → TapokHub («Ввести адрес сервера вручную» или из буфера обмена), плагин проверяет его по `/healthz`, при смене сервера сбрасывает вход прежнего; картинки хаба берутся с сервера человека. Плагины со вшитым адресом работают как прежде. В nginx-конфигурацию добавлен маршрут `/healthz` (`deploy/nginx/nginx-tapokhub-proxy.conf`, появляется при обновлении установщиком).
- **HTTPS в Docker Compose одной настройкой.** В `compose.yaml` появилась необязательная служба Caddy (профиль `https`, по умолчанию выключена): `TAPOK_DOMAIN` и `COMPOSE_PROFILES=https` в `.env` включают сертификат Let's Encrypt, убрать профиль и `docker compose rm -sf caddy` выключают. Адрес посетителя идёт в `X-Real-IP`, а сервер верит ему только от адресов из новой переменной `TAPOK_TRUSTED_PROXIES` (в compose это адрес Caddy).

## 0.9.0-pre.5 (pre-release)
- **Английский язык.** Интерфейс плагина выбирается по языку Lampa (русский, украинский и белорусский дают русский интерфейс, остальные английский): все тексты плагина идут через `TH.t()`, русский текст служит ключом, английский лежит в `plugin/src/core/i18n-en.js`. Ответы сервера плагину следуют заголовку `Accept-Language` (плагин ставит язык Lampa), Telegram-бот отвечает на языке Telegram собеседника, команды администратора, журнал, страница-подсказка и скрипты установки берут язык из `TAPOK_LANG`, иначе из языка системы, иначе русский (`server/tapokhub/core/i18n.py`, каталог `i18n_en.py`). Язык описаний TMDB сервера по умолчанию тоже следует `TAPOK_LANG`. Полнота английского каталога проверяется тестами (`plugin/tests/i18n.js`, `server/tests/test_i18n.py`). Документация на английском: `README.en.md`, `docs/en/`, `server/README.en.md`, `CHANGELOG.en.md`.
- **Демо-сервер.** Пределы на пользователя: `TAPOK_LIMIT_MOVIES`, `TAPOK_LIMIT_TV`, `TAPOK_LIMIT_FRANCHISES` (владельца они не касаются), а команда `tapokhub users limit` задаёт свои пределы одному пользователю. Плагин показывает сообщение сервера, когда предел достигнут. В README добавлена ссылка на открытый демо-сервер.

## 0.9.0-pre.4 (pre-release)
- **Регистрация на сервере** переключается в плагине: Настройки → TapokHub → «Регистрация на сервере» → «Открытая» или «Закрытая». Видит и меняет значение только владелец сервера (первый пользователь), остальным строка сообщает, кто это настраивает; сервер отвечает 403 на чужую попытку (`GET`/`POST /lib/registration`). Команда `tapokhub users registration open|closed` работает как прежде.
- Репозиторий переехал на `TAPOKSYS/TAPOKHUB-Lampa-addon`; образ Docker теперь `ghcr.io/tapoksys/tapokhub-lampa-addon`. Ссылки в документации, `install.sh` и `compose.yaml` обновлены.
- **Руководство** `docs/GUIDE.md`: развёртывание (установщик, Docker, Docker за своим nginx), все функции с картинками, Telegram-бот, управление сервером, копии и откат, справочник. Снимки экранов сняты на настоящей Lampa скриптом `scripts/docs-screenshots.py`.
- **Второй аудит кода**, исправления: очистка кеша ответов TMDB (предел 512 МБ; раньше рос без границы), пределы на пользователя (5000 позиций, 300 коллекций), ключ TMDB сервера запоминается только из запросов владельца, бот не останавливается молча при обрыве ответа Telegram, команды `tapokhub telegram list|clear`.
- **Telegram-бот** (Настройки → TapokHub → Telegram): токен бота от @BotFather вводится в плагине и хранится на сервере, отдельный процесс не нужен. Номер чата вводить не нужно: после токена достаточно отправить боту `/start`, личный чат привяжется сам (окно привязки 5 минут после ввода токена или кнопки «Привязать чат», только личные чаты; группу привязывают вписыванием номера; страница следит за состоянием и сообщает о привязке). Бот ищет фильмы и сериалы по названию, добавляет и убирает из библиотеки, включает и выключает отслеживание коллекции; команды `/library`, `/regen`, `/id`. Отвечает только в своём чате (кроме `/id`, чтобы узнать номер чата), токен наружу не отдаётся и в журнал не попадает. Проверка токена и тестовое сообщение при сохранении; API `GET/POST /lib/telegram`.
- **Автозапуск хаба** (Настройки → TapokHub → «Запускать хаб при старте Lampa», по умолчанию выключен, только для этого устройства): после запуска Lampa идёт отсчёт 5 секунд и открывается хаб. любая нажатая кнопка, касание, клик или колесо мыши отменяют запуск (обычные кнопки работают как всегда, «Назад» дополнительно гасится, чтобы Lampa не вышла из приложения); если человек сам открыл другой раздел, запуск по ссылке на фильм или хаб уже открыт, отсчёта нет.
- Токены не нужно печатать: кнопки «Вставить … из буфера обмена» для токена Telegram-бота (ищется внутри вставленного текста, можно скопировать сообщение @BotFather целиком), номера чата и токена доступа TapokHub. Если буфер недоступен (телевизор, http), сразу открывается ручной ввод. На странице Telegram показано, к какому аккаунту привязан бот: он один на все устройства этого аккаунта CUB.
- В настройках TapokHub появилась строка «Сервер»: версия сервера и способ запуска («Docker» или «без Docker»). Сервер отдаёт `runtime` в `/health` (`TAPOK_RUNTIME`, образ ставит `docker`).

## 0.9.0-pre.3 (pre-release)
- **Docker**: образ в одном контейнере без nginx (`Dockerfile`, `compose.yaml`, `docs/DOCKER.md`); образы `amd64` и `arm64` публикуются в `ghcr.io/petefree1/tapokhub-lampa-addon`. Токен доступа создаётся при первом запуске, почта администратора и регистрация задаются переменными окружения, проверка образа: `scripts/docker-test.sh` (она же в CI).
- **Работа без домена по http**: `install.sh` без `--domain` ставит сервер на адрес компьютера (`--host http://192.168.1.5`, по умолчанию определяется сам). Сервер умеет сам отдавать плагин, картинки и страницу-подсказку (`TAPOK_WEB_DIR`), подставляя в плагин адрес, по которому к нему обратились, и отвечает на `/healthz`.
- «Библиотека»: позиции делятся на группы: фильмы, сериалы, мультфильмы, мультсериалы, аниме и манга (ключевые слова anime/manga/based on manga, в том числе игровые экранизации, и японская анимация), документальные. Сверху кнопки-фильтры («Все» и по группам, со счётом); выбранная подсвечена. Группу определяет сервер (поле `group` в `/lib/items`); с прежним сервером плагин делит по виду фильм/сериал.
- Плагин запускается на Lampa 3.0.5 и новее (раньше порог был 3.3.0, и на 3.0.5 плагин сам себя отключал: хаб не появлялся). Пункт «TapokHub» в боковом меню стоит третьим; порядок записывается в настройки меню Lampa один раз, дальше его можно менять в редакторе меню.
- Контент для взрослых исключается из коллекций: признак TMDB `adult` и ключевые слова эротики (erotic movie, softcore, sexploitation, erotica) скрывают позицию автоматически (в «Настроить» она видна в «Прочее», вернуть можно вручную); из поиска и рекомендаций он убран совсем.
- Удаление фильма из коллекции: долгое нажатие на карточку → «Убрать из коллекции» (возвращается через «Настроить»).
- Логотип и обложка составной вселенной (Marvel, «Волшебный мир») больше не берутся у первой части одной из её коллекций: раньше вселенная Marvel подписывалась логотипом «Железного человека». Теперь у такой вселенной текст названия, обложка по лучшему рейтингу.
- Новая настройка «Открывать фильм сразу через торрент» (Настройки → TapokHub → Воспроизведение, по умолчанию выключена): Enter на карточке в хабе минует страницу фильма. Торрент выбран — запускается; не выбран — открывается поиск по парсеру.
- Экран коллекции: стартовый фокус на первой карточке фильма, а не на кнопке «Настроить»; у кнопки настоящая шестерёнка.
- `deploy/setup.sh` видит подключение к nginx через симлинк в `sites-enabled` (раньше добавлял второй `include`, и nginx отклонял конфиг).
- Локальные торренты и настройки разделены по серверу и токену; ответы и очереди прежнего аккаунта не затрагивают новый.
- Подтверждённые записи, удалённые на другом устройстве, больше не загружаются обратно; очистка подтверждается после ответа сервера.
- Очередь изменений настроек сохраняется до подтверждения и повторяется после сетевой ошибки, включая перезапуск приложения.
- Ручной токен проверяется до переключения аккаунта; поздний ответ входа после выхода игнорируется.
- Готовый релиз устанавливается без Node.js. Отказ перезапуска и неверная версия health-check восстанавливают прежний релиз и unit, включая старую схему запуска.
- Ограничение попыток входа не доверяет клиентским CF-Connecting-IP/X-Forwarded-For; X-Real-IP принимается только от локального прокси.
- Объединение пользователей переносит настройки и торренты одной транзакцией; при совпадениях сохраняется более поздняя запись.
- Закрываются SQLite-соединения потоков и фоновая очередь библиотеки; тестам больше не требуется увеличенный лимит открытых файлов.
- Добавлены регрессионные проверки плагина, сервера и выкладки в `scripts/test.sh`.

## 0.9.0-pre.2 (pre-release)
- **Установка одной командой** на Debian/Ubuntu: `curl … install.sh | sudo bash -s -- --domain … --email …`. Скачивает релиз
  с GitHub, проверяет контрольную сумму, ставит nginx и python3, настраивает HTTPS (Let's Encrypt), выкладывает сервер и плагин.
- Плагин из релиза получает адрес сервера пользователя (`deploy.sh --host`), адрес запоминается для обновлений.
- На новой установке регистрация закрыта, почта администратора записывается при установке.
- `deploy/setup.sh` (бывший `install.sh`): отдельный сайт nginx для домена, откат изменений nginx при ошибке.
- Команды `tapokhub rollback` и `tapokhub uninstall [--purge]`; скрипты выкладки остаются на сервере в `/opt/tapokhub/deploy`.
- Описание для пользователей (README со снимком экрана), `docs/INSTALL.md`.
